# 面向患者家属的站点改造设计

日期：2026-07-31
状态：已确认，进入实现

## 背景

`website/` 目前是一个面向研究者的书目检索站：63 条记录、hero + 统计磁贴 + 客户端 `PaperExplorer` + 每条记录一个详情页。对普通人（患者与家属）存在以下障碍：

- 卡片题名**只有英文**；中文 `notes` 字段（中位长度 21 字）从不显示在卡片上。
- 中英文在同一行交错（`开始检索 / Search`、`全文记录 / Full-text record`）。中文/English 切换只作用于 `PaperExplorer.tsx`，hero、统计、整理原则、页脚和整个详情页都是写死的双语。
- 术语面向研究者：`NON_FULLTEXT`、访问卡、持久标识、溯源、SHA-256、PMCID。
- 检索是对原始元数据的严格 AND 子串匹配，口语词（「运动 猝死」「胸痛」）返回零结果且无降级。
- 没有任何内容解释 AAOCA 是什么，也没有指出该从哪里读起。

## 决策

| 决策点 | 结论 |
|---|---|
| 目标人群 | 患者与家属优先 |
| 新增内容 | 允许新增中文题名、白话摘要、主题标签；AI 起草，人工复核 |
| 双语策略 | 中文优先，英文可用；英文独立路由树 |
| 主任务 | 先理解病情，再按问题浏览 |
| 实现方案 | 方案 B：问题页作为真实路由 |

## 数据层

新增 `website/data/plain-language.json`，以 `sha256` 为键，字段：

- `title_zh`：中文题名，可选（原题已是中文时省略）
- `summary_zh`：2–3 句白话摘要
- `topics`：1–3 个主题 slug
- `reviewed`：布尔值，是否经人工核对

`lib/library.ts` 增加 `enrich()` 合并步骤，导出 `Paper & PlainLanguage`。无对应条目的记录仍正常渲染（回退到英文题名、不显示摘要），保证撰写过程中站点不会中断，也便于分批复核。

**不写入** `index/bibliography_and_access_status.json`：该文件由 `scripts/sync-index.mjs` 每次构建从仓库根目录整体复制，用途是校验和与路径；编辑性文字写进去会和同步机制冲突，也会污染溯源数据的职责。

### 主题分类

| slug | 中文 | 覆盖范围 |
|---|---|---|
| `what-is-it` | 这是什么情况 | 解剖、分类、患病率、病例系列 |
| `how-serious` | 严不严重 | 风险分层、猝死、自然病程、登记研究 |
| `what-tests` | 需要做什么检查 | CTA、MRI、超声、负荷试验、FFR、缺血评估 |
| `sports` | 还能运动吗 | 运动参与、锻炼、恢复比赛 |
| `surgery` | 要不要手术 | 手术指征、术式、术后结局 |
| `guidelines` | 医生依据什么 | 专家共识与临床指南 |

主题在撰写时逐条人工指定，不用正则匹配。一条记录最多 3 个主题。

## 路由结构

```
/                      中文落地页
/topics/[slug]         六个问题页
/papers/[slug]         记录详情页
/en                    English landing
/en/topics/[slug]
/en/papers/[slug]
```

静态导出约 140 页（每边 1 + 6 + 63）。

**不**使用 `app/[lang]/` 动态段——根路径会变成 `/zh`，而静态导出没有 middleware 做重定向。改为页面主体抽到 `components/pages/`，接受 `lang` 参数，由 `app/page.tsx` 与 `app/en/page.tsx` 两个薄壳分别渲染。

## 双语机制

文案集中到 `lib/i18n/zh.ts` 与 `lib/i18n/en.ts`，共用 `Dictionary` 类型。

`PaperExplorer.tsx` 内部的 `copy` 对象与 `language` state 全部删除，改为从 props 接收字典。语言从组件状态变为路由事实，一并消除 localStorage 持久化、hydration 不匹配，以及切换语言后 `<html lang>` 不变这三个问题。

语言切换做成指向对应路径的链接；每页 metadata 的 hreflang 指向真实对应 URL，修复 `app/layout.tsx:24-27` 把 `zh-CN` 和 `en` 都指向 `/` 的空声明。`app/sitemap.ts` 扩展以包含问题页与英文树。

## 页面结构

**落地页**：一句话说明 + 免责声明 → 手写「这是什么情况」科普段 → 六张问题卡片 → 全部文献检索区 → 整理原则 → 页脚。

**问题页**：标题即问题 → 手写引导语（该问题证据现状、为何必须与医生讨论）→ 记录列表（共识指南优先、全文次之、非全文最后）→ 相关问题链接。

**详情页**：中文题名作 `h1`，英文原题作副标题保留 → 白话摘要 → 「能不能看到全文」状态 → DOI/PMID/PMCID 加「把这个编号给医生或图书馆」→ SHA-256、路径、字节数收进 `<details>`。

## 检索改造

1. 索引扩展到 `title_zh`、`summary_zh`、`topics`。
2. 新增 `lib/synonyms.ts`：口语词映射到记录中真实存在的词（猝死 → sudden death / risk，心脏 CT → CTA / computed tomography，开刀 → surgery / unroofing，胸痛 → chest pain / symptom 等）。
3. 零结果降级：全词 AND 匹配为空时退回任意词匹配，并提示「没有完全符合的，以下是部分相关的」。
4. 筛选标签口语化：「获取状态」→「能不能看到全文」，「文献类型」→「只看共识和指南」。

## 安全表述

1. 摘要只复述研究说了什么，统一句式「这项研究纳入了⋯⋯，结果发现⋯⋯」，不出现「应该」「建议你」「可以放心」。
2. 免责声明进首屏，平实表述：「本站整理公开发表的研究文献，帮助你和医生讨论，不能替代医生的诊断和建议。」
3. `reviewed: false` 的条目渲染「AI 初稿，待人工核对」标记。
4. 不做风险自评、不做分诊交互。
5. 问题页引导语写明：不同研究结论可能互相矛盾，共识和指南才是医生的主要依据。

## 非全文记录

32 条访问卡措辞改为「本站没有全文 · 需要到期刊网站获取」，详情页补「可以凭 DOI 编号请医生、医院图书馆或大学图书馆代为调阅」。每个问题页内排最后，**不隐藏**——隐藏会违背仓库自身写明的整理原则。

## 视觉与无障碍

- 正文字号上调到 17–18px，行高维持 1.6。
- `--sans` / `--serif` 字体栈把中文字体前置。
- 680px 以下分段筛选按钮触控高度 ≥44px。
- 对比度实测 `--ink-soft` 配 `--paper`，以及 `--gold` 作文字色的情况。
- 不引入深色模式，不更换设计语言。

- 新增：六个问题页全部生成且无空页。
- 新增：`plain-language.json` 每个 key 都能对上现有 sha256。
- 新增：中英文树页面数一致，hreflang 互指。
